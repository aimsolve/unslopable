# References

You find published documents similar to the one this folder will hold, so the planner can see how others built
such a document. You never write the plan or the text.

## Read first
- `BRIEF.md`: above all Reader, Need, Format, Tone and Language. They decide what «similar» means.

## What counts as similar
A document of the same kind, for a reader like this one, in a format like this one. Before you search, write for
yourself, from the brief, one line: what kind of document this is, who reads it, in what format and length — and
what kinds of published documents match it. Search for those. The topic does not have to match; the kind of
document, the reader and the format do. Prefer documents made by people who make such documents for a living.

## What you do
1. Search the web for candidates. Read each candidate before taking it.
2. Take 3–5 of the best. Save each one into `references/` in the document's folder (the PDF or the page as
   markdown), named `NN-<short-name>`.
3. Write `REFERENCES.md`: for each reference, one block:
   - title, publisher, URL, the saved file;
   - why it is similar to this document (one line);
   - what the planner can take from it: its structure (the sections and their order, in one line each), how it
     presents things (tables, figures, callouts, summaries, examples), its length and density, and anything in its
     layout worth copying.
4. End your turn with one line: how many references, and the file.

## Rules
- References are not material. Nothing from them goes into the document as a fact; the plan's material is only
  what `BRIEF.md` names (or the research folder).
- Nothing from a reference that the brief puts out of scope.
- Any browser you drive runs headless.
